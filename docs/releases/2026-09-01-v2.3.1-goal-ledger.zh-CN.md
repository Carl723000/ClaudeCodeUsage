## G2 入口审计

以下是必须先用最小 fixture 复现、再修改实现的风险假设，不代表已接受的现有行为：

1. 每周定价覆盖率疑似使用完整窗口，而不是截至观测时刻的前缀。
2. 精确内容去重签名未纳入日/周期分布，可能把总量相同但日期不同的记录折叠掉。
3. `codex-spark` 限额可能被误判成账号级，而实际作用域是特定模型。
4. 重置后延迟到达的当前观测可能掩盖有效的重置前缓存观测。
5. 累计 delta 修复可能产生 `reasoning > output` 或 `cached input > input`。
6. 部分 effort map 的剩余用量可能消失，而不是归入 `unknown`。

额外 guard 覆盖配置时区下完整的 30 天定义、跨年月份正序、reasoning-effort 别名/非法变体，以及日、月、模型、effort 和总计之间的守恒关系。

## G2 正确性证据

### 根因修复

- active/archive 精确去重签名现包含权威 all-time `byDay` 分布，因此“总量相同、日期不同”不会被静默折叠。可重建的 `period`/`today` 投影不进入身份签名，避免 sidecar 迁移时破坏刷新幂等；它们继续由独立可读性检查保护。
- 周额度推断改用截至观测时刻的已定价 Token 覆盖率，而不是同周后续记录；后到的已定价行不能再把证据不足的前缀变成可推断样本。
- 显式模型级 Codex `limitId` 优先于通用 `limitName`，防止 Spark 等独立额度混入账号级序列。
- reset 时刻或之后才写入的延迟 poll 不再遮蔽有效的重置前缓存观测。
- 累计 Token delta 强制 cached input ≤ input、reasoning ≤ output；修复事件标为 partial，并保持 processed 只计一次。
- 部分 model/effort map 的正残差进入 `unknown`；aggregate 与线程投影均删除零值 bucket。

### 真实 schema 的 effort 审计

- 本地只做字段路径计数，不输出文件名、字段值、时间或日志正文。有限扫描中观察到 51,912 个 `turn_context.payload.effort`、33,403 个 `thread_settings_applied` 变体和 33 个显式 completed-item 变体。
- 白名单路径中的字符串都可规范为 `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max` 或 `ultra`；另有 1 个显式 null 保持未归属。解析器现支持这些显式新旧路径，绝不按模型名称推断 effort。

## G2 entry audit

The following implementation risks are test hypotheses, not accepted behavior. Each must first be reproduced by a minimal fixture before its implementation changes:

1. Weekly pricing coverage appears to use the whole window rather than the observation-time prefix.
2. Exact-content deduplication does not include day/period distribution and can collapse records with equal totals but different dates.
3. A `codex-spark` limit may be classified account-wide when its scope is model-specific.
4. A delayed post-reset current observation may mask a valid cached pre-reset observation.
5. Cumulative-delta repair may permit `reasoning > output` or `cached input > input`.
6. Residual usage in a partial effort map may disappear instead of being attributed to `unknown`.

Additional guards cover the complete 30-day definition in the configured timezone, cross-year chronological month order, alias/invalid reasoning-effort variants, and conservation across daily, monthly, model, effort, and total views.

## G2 correctness evidence

### Root-cause fixes

- Exact active/archive deduplication now includes the authoritative all-time `byDay` distribution, so equal totals on different dates cannot silently collapse. Rebuilding `period`/`today` projections intentionally remain outside identity, preserving refresh idempotence while their independent readability checks run.
- Weekly allowance inference gates on priced-token coverage up to the observation timestamp, not later rows in the same week. A later priced row can no longer make a weak prefix look sufficiently priced.
- An explicit model-specific Codex `limitId` takes precedence over a generic `limitName`, preventing Spark and similar allowances from entering the account-wide series.
- A delayed poll written at or after reset no longer shadows a useful cached pre-reset observation.
- Cumulative token deltas clamp cached input to input and reasoning to output, mark the repaired event partial, and continue to count processed tokens exactly once.
- Partial model/effort maps send positive residual components to `unknown`; zero-value buckets are removed from aggregate and thread projections.

## G3 quota-observation and weekly-estimate evidence

### Persisted observation boundary

- Added a schema-versioned, provider/account/window-partitioned observation store with machine-local HMAC fingerprints. Raw credentials and identity signals are discarded after fingerprinting; Webview projections receive only per-run ephemeral aliases.
- Observation writes use a same-directory `0600` temporary file, `fsync`, and atomic rename. A cross-process lease, locked re-read, canonical deduplication, 180-day retention, and bounded compaction make repeated refreshes stable without merging account epochs.
- Strict validation quarantines corrupt or future-schema files instead of trusting or deleting them. Legacy P3/P4 global-state observations and P5 Codex index history migrate P2-first; source keys and migration markers advance only after the destination append succeeds, so an interrupted migration retries safely.
- Claude account continuity is derived only after a successful quota response from a one-way refresh-token HMAC. The token itself is never returned, persisted, logged, or exposed to the Webview. Codex observations use the same store and privacy projection.

### Reset detection and allowance inference

- Reset events are derived at runtime from provider window identity, changed `resetAt`, or a significant used-percentage rollback. Account changes alone do not invent an official reset; same-day and consecutive-day resets remain distinct.
- Every valid observation with `0 < usedFraction ≤ 1` contributes `priced usage through observedAt ÷ usedFraction` as a candidate total. A weighted robust median combines candidates while pricing coverage, log coverage, boundary precision, and attribution determine confidence.
- Estimated total is never lower than confirmed used value. Unused value is clamped non-negative and appears only for a closed window with reliable account attribution, boundary continuity, and sufficient pricing coverage.
- A single coherent unattributed Codex window may expose a low-confidence total but never unused value. Overlapping or multi-account ambiguity degrades to used-only instead of inventing an account split.

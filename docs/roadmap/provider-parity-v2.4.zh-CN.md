# v2.4 Claude / Codex 交互一致性路线图

本路线图承接 v2.3.1 的回归修复，目标是在不混淆两家 provider 指标语义的前提下，让相同类型的信息采用相同的交互、视觉层级、键盘行为和反馈方式。它不是 v2.3.1 发布范围；每项进入实现前都要先补最小失败夹具。

当前审计台账：[简体中文](provider-parity-matrix-v2.4.zh-CN.md) ·
[English](provider-parity-matrix-v2.4.md)。

## P0：交互清单与独立审计

- 建立 Claude / Codex 逐组件对照表：状态栏、额度 tooltip、摘要卡、图表、表格、折叠项、空状态、加载/失败状态、筛选、排序、下钻、返回路径、窄屏和深浅主题。
- 增加任何下钻入口前，先证明各 provider、各数据源确实具备所需聚合；Codex 已物化小时侧车是首个可行性门。若某个来源无法如实支持同一层级，应记录为“刻意保留的语义差异”，改用 provider 合适的详情或不提供入口，不能做无响应或虚构的图表。
- 用 Claude CLI 对生产 HTML/CSS/TypeScript 和真实安装截图做一次只读审计，输出“缺失、行为不同、视觉不同、刻意保留语义差异”四类问题。
- 审计不得读取或输出账号、路径、线程标题、prompt、日志正文或凭证；只允许代码、合成 fixture 和隐私安全截图。

## P0.5：v2.3.1 独立审阅后采纳的后续项

截至 v2.3.2 稳定分支启动时，本组采用项的状态如下。提交号属于本地候选分支，只有
经维护者审阅并合入后才成为发布证据。

## P1：图表按时间层级下钻

- 全部时间的月柱：点击或按 Enter/Space 后展开该月的每日数据；v2.3.2 候选已为
  两个 provider 实现（`f51f29c`）。
- 最近 30 天的日柱：点击或按 Enter/Space 后展开该日的小时数据；v2.3.2 候选已
  物化两个 provider 的对应路径（`84c84d7`）。
- 今日的小时柱：保持同一选中/高亮/详情反馈，不制造无法从本地索引支持的更细粒度。
- Claude 与 Codex 共用同一套选中态、`aria-expanded`、`aria-controls`、焦点、空数据提示、返回/收起入口和响应式布局。
- 下钻只能使用已物化的日/月/小时聚合；点击时不得重新扫描 JSONL。若小时侧车仍在迁移，显示明确的小计/覆盖率，不回退到未经验证的旧总量。
- 实时刷新后保留展开链、所选周期、键盘焦点和滚动锚点。v2.3.2 候选已为普通 Claude/Codex 同骨架更新实现并测试该契约（`3b46c09`）；结构变化仍走完整重载路径。
- 在选定范围内补齐无活动的日期/小时为零，避免稀疏记录扭曲坐标轴或让层级看起来短于请求范围。
- 小时图继续保留全部补零时段、坐标轴标签和表格行，但不再在柱顶重复显示 0；
  真实存在但无法定价的活动仍显示 `—`，不会被误认为没有活动（`c991d4f`）。

## P2：状态栏与额度详情

- 两个 provider 的主状态项都以配置时区下的“今日”作为范围，并在 tooltip 中使用结构化表格。
- 5 小时/每周额度统一使用“已用百分比”、同一绿色/黄色/红色阈值、同一进度条、重置时间列和键盘可达入口。
- 状态项背景色由当前偏好实际显示的所有有效窗口中最危险者决定；已过期或无观测状态不得遗留警告色，也不得显示只有表头的空 tooltip。
- provider 特有的证据边界保留原意：Claude 为官方 `/usage`，Codex 为本地最后观测；不得用视觉一致性暗示数据权威性等价。

## P3：组件和状态一致性

- 摘要卡：密度、数字字体、单位、帮助文本、零值、未定价和索引小计样式一致。
- 表格：排序、数值对齐、行展开、滚动容器、空行和窄屏行为一致。
- 折叠项：默认开合状态、summary 命中区、焦点样式和状态持久化规则一致。
- 加载、空数据、部分索引、过期观测和错误状态使用同一信息层级，但保留 provider 专属原因。
- 每张图都提供带 provider 名称的可访问文本替代。v2.3.2 候选已为全部图表滚动区和热力图补齐名称，并用完整 Axe/键盘测试验证 Compare 名称唯一（`fc6f53b`）。
- Compare 只比较可比较的活动量，不相加账单、额度或能力。

## P4：验收门

- 持续维护可追踪的 [provider 一致性矩阵](provider-parity-matrix-v2.4.zh-CN.md)；每个差异标记为“已对齐”或“刻意不同”，后者必须写明语义理由。
- Node 夹具覆盖非 UTC 与 DST 守恒（`小时之和 = 日`、`日之和 = 月`，且 Today 使用同一日表）、点击零额外 JSONL 读取、额度阈值和状态栏范围。
- Playwright 覆盖鼠标、Enter/Space、ARIA、焦点、Light+/Dark+、360 px、最长语言和逐级下钻/收起。
- 在隔离 VS Code profile 安装 VSIX，至少截取 Claude/Codex 今日状态栏、额度 tooltip、月→日和日→小时四组隐私安全实图。
- Claude CLI 首轮只读审计后只允许一次针对已选问题的修订复核；阻塞问题关闭后才进入候选打包。

## 远期候选（v2.6+）：Remote-SSH／多主机用量聚合

本项明确不进入 v2.4 或 v2.5，也不阻塞其发布。近期继续保持“每个 Extension Host
只读取一个本机 `CODEX_HOME`”的边界：Remote-SSH 用量只有在插件实际运行于对应
远端 Extension Host 时才能单独查看；本机与多个远端不会自动合并。

- 若未来实施，默认仍关闭，并要求用户显式选择和配对主机；不得把 SSH 连接能力、
  后台同步或远端扫描悄悄加入普通刷新路径。
- 主机之间只允许交换带版本、受大小限制的脱敏数值聚合与覆盖元数据。不得传输原始
  JSONL、prompt／response、线程标题、绝对路径、用户名、凭证或完整账号标识。
- Token 活动可在稳定的匿名主机／来源边界内去重后求和；账号额度快照绝不能按主机
  相加，只能按额度系列采用最新有效观测，并明确显示来源主机、观测时间和过期状态。
- 仪表盘必须同时显示综合值与逐主机覆盖率；离线、断连、时区差异、同一会话跨主机
  重放和一个 home 多登录都要降级为可见的不确定性，不能伪造完整历史。
- 进入实现前须另立设计与隐私安全门，验证 Remote Extension Host 生命周期、断线续传、
  原子检查点、跨主机去重、资源上限和可逆清除；通过前不承诺具体发布版本。

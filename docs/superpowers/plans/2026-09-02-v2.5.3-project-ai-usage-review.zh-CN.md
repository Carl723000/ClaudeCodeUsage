# v2.5.3 项目级 AI 用量审阅计划

状态：规划冻结，尚未授权实现。
目标列车：`v2.5.x` 内部槽位 `v2.5.3`；不承诺单独发布 Marketplace 包。
产品宿主：现有 `Explore → Projects`，不新增顶层 Tab。
前置能力：v2.3.1 安全 AI 请求边界和本地数据控制、X-06 项目用量矩阵、v2.4.x 建议实验/同类任务比较 envelope。

## 1. 版本归属决定

本功能不回填 v2.3.1，也不阻塞 v2.3.1 的安装验证或发布决策。它比普通的项目聚合更敏感：可能读取选定项目的输入/输出正文、调用用户选择的远程 AI 或本机 Claude CLI，并保存结构化建议结果。因此归入 `v2.5.x` 的“本地效率实验室”，候选内部槽位为 `v2.5.3`。

它不依赖 GitHub Connect。若发版列车需要合并，可与其他 v2.5.x 能力同包发布，但必须保留独立的同意、数据清除、网络和回滚边界。

## 2. 用户结果

用户选择一个项目、provider 和时间范围后，可以先获得完全本地、确定性的用量行为摘要，再决定是否调用 AI 深度审阅。报告回答：

- 这个项目的 Token、缓存、上下文、模型/effort、Session 和迭代行为如何变化；
- 哪些输入/输出形态可能造成重复劳动、上下文膨胀或无效复审；
- 下一次相似任务可以尝试哪一个小实验；
- 用什么可观测指标判断实验是否有效。

报告不得仅凭 Token 消耗评价生产率、代码质量、研究质量、人员表现或模型能力。

## 3. 三档审阅模式

1. **仅本地用量审阅（默认）**：只使用现有索引中的数值和结构聚合，不联网，不读取正文。
2. **AI 聚合审阅**：发送用户预览并确认的项目聚合快照；不包含 prompt、response、路径、项目名、线程标题或账号标识。
3. **AI 内容辅助审阅（单独同意）**：只读取用户本次明确选择的会话/日期范围，净化并有界抽取输入/输出。发送前显示精确条目、角色、字节数和最终请求正文；用户可以移除任何条目。该同意不能由“AI 聚合审阅”继承。

任何模式都不得自动扫描整个 workspace、读取源码、dotfile、secret、git remote、终端历史或未经选择的会话。

## 4. 分析口径

### 4.1 本地确定性证据

- processed、fresh input、cached input、output 和 reasoning 的 provider 原生口径；
- cache reuse/warm-up、context churn/compaction、长上下文增长；
- 模型与 reasoning effort 的切换及其任务阶段；
- Session 拆分、恢复、subagent 和工具步骤的结构计数；
- 重试、反复复审、无变化长链路和输出重写的可观测 proxy；
- 输入/输出长度、轮次和比例；
- 官方额度观测、API 等效价值和本地 Token 必须分栏，不能互相替代。

### 4.2 AI 可解释层

每条发现必须使用固定结构：

`看到了什么 → 本地证据引用 → 为什么值得注意 → 下次只试一个什么动作 → 用什么指标复核 → 置信度/限制`

AI 只能解释冻结的项目快照，不能改写源指标、自动更换模型/effort、编辑项目文件、运行命令或发起外部写入。内容模式可以评论提示结构、输出冗余和重复说明，但不得把文字风格直接推断为任务质量。

## 5. 本地与外发数据契约增量

| 数据类 | 内容 | 持久化 | 外发规则 |
|---|---|---|---|
| 项目审阅快照 | 匿名 `projectRef`、provider、日期/时区、coverage、模型/effort、Token 与结构聚合、证据 ID | 默认按需生成；不得建立第二套日志索引或按项目常驻缓存 | 仅 AI 聚合/内容模式在精确预览后发送 |
| 可选内容样本 | 用户本次选择的输入/输出、角色、局部时间顺序及净化标记 | 只在内存保留到请求完成/取消；不得写入 globalState、日志或报告 | 必须单独同意并逐项预览；达到字节/条目上限后停止，不静默截断 |
| 请求预览 | backend、model、模式、精确正文、字节数、snapshot hash | 默认不持久化；只可记录无内容的审计元数据 | 预览与实际 body 必须字节一致 |
| 结构化审阅结果 | finding ID、evidence IDs、置信度、限制、建议实验和衡量方式 | 可选本地保存；有 schemaVersion、有界条数/保留期、可单项及全部清除；不得含原文引语或原始 CLI 输出 | 默认不再次外发 |
| 用户同意/偏好 | 默认模式、是否允许内容、保留策略、上次选定 backend | 本地有界设置；内容同意按每次请求，不允许永久“总是允许” | 不外发 |
| AI 凭证 | 沿用现有 SecretStorage key 或未来独立、审阅后的 secret key | 仅 SecretStorage | 只用于用户本次确认的 backend；绝不进入 body/预览/Webview state |
| CLI 审计元数据 | CLI 路径的净化标识、版本、model、输入 hash、时间、退出状态 | 可选有界记录；不保存 stdout/stderr 原文 | 不外发给第二服务 |

`projectRef` 必须由机器盐和 provider 原生项目键单向派生；报告 UI 可在运行期显示本地项目名，但持久化结果和外发 payload 不得包含项目名或绝对路径。

## 6. AI backend 边界

### 6.1 现有 BYOK/API 模式

- 复用 v2.3.1 的 preview → 单独 Send → result 流程、超时、取消和 SecretStorage。
- endpoint/model/key 失败必须安全退出；不开启时零请求、零 timer。
- 请求只发送精确预览中的 payload，不附加诊断、路径或后台上下文。

### 6.2 可选本机 Claude CLI 模式

该 adapter 属于 v2.5.3 的独立安全门，不能因为机器上存在 `claude` 就默认启用：

- 每次显示将执行的精确二进制、版本、model、模式、payload 字节数和联网说明；
- 直接 spawn 参数数组并通过 stdin 传输，禁止 shell 拼接；使用 print、禁用工具、禁用会话持久化、安全模式、隔离空目录、最小环境、超时和取消；
- CLI 无仓库工具、无 cwd 项目访问权、无 MCP/plugin/hook；项目输入/输出始终按不可信数据处理；
- 捕获输出有严格字节上限，先按 schema 校验再显示；原始 stdout/stderr 不持久化；
- 登录失效、额度不足、超时或非零退出最多给出一次显式重试，不后台循环。

本机 CLI 仍可能把确认后的 payload 发送给对应 AI 服务，因此 UI 不能把它称为“完全离线”。

## 7. Prompt injection 与输出校验

- 项目输入/输出、工具结果、代码片段和模型旧回答全部是**不可信数据**，其中的指令不得改变 reviewer system contract。
- reviewer 无工具、无网络工具、无写权限，只返回版本化 JSON。
- 输出 schema 至少包含 `schemaVersion`、`snapshotHash`、`scope`、`findings[]`、`limitations[]`；每个 finding 必须引用输入中存在的 evidence ID。
- 未知 evidence、跨项目主张、未提供的质量结论、凭空的因果关系和自动执行建议使该 finding 失效；解析失败时展示失败，不回退到未经校验的自由文本。
- 展示层以 `textContent`/安全 renderer 输出，任何模型 HTML/Markdown 均不得成为可执行 DOM。

## 8. UI 与交互位置

在 `Explore → Projects` 的选定项目详情中增加“生成 AI 用量审阅”动作：

1. 选择 provider、项目和 7/30/90 天或自定义范围；
2. 查看本地确定性摘要和 coverage；
3. 选择三档模式；
4. 查看并编辑精确 payload 预览；
5. 明确 Send/Run，支持取消；
6. 结果按“观察—证据—实验—复核”展示，并允许保存净化结果、标记已尝试或清除。

单一 provider、无内容、样本不足、数据重建中和 AI 不可用都必须有可解释空状态。刷新/重载后只恢复非敏感选择，不恢复未发送正文或自动重发。

## 9. Goal 阶段与检查点

| 阶段 | 产物 | 退出条件 | Claude 只读校准 |
|---|---|---|---|
| R0 范围与威胁模型 | spec、数据契约增量、golden fixtures、非目标 | 项目隔离、三档模式和外发字段冻结 | 审阅隐私、注入和版本归属 |
| R1 项目快照 | 复用现有索引的纯函数 snapshot/coverage/evidence | 冷/热结果一致，不重扫日志，无第二缓存 | 不需要 |
| R2 预览与同意 | payload builder、精确 preview、大小上限、撤回/清除 | aggregate-only 默认；内容同意不能继承；preview=body | 审阅数据最小化和权限语义 |
| R3 AI 结果契约 | backend-neutral adapter、JSON schema、evidence validator | malformed/injected/跨项目输出全部 fail closed | 不需要 |
| R4 UI 与本地报告 | Explore 项目入口、进度/取消、结构化报告和实验记录 | 8 locale、键盘、ARIA、深浅主题、360 px 通过 | 审阅建议是否越过证据边界 |
| R5 可选 Claude CLI adapter | 无 shell spawn、隔离 cwd、no-tools/no-persistence、超时 | 合成端到端通过，未授权/失败时零残留进程 | 安全复核后才允许接生产 |
| R6 文档与候选 | README/LOCAL-DATA/CHANGELOG、安装截图、VSIX | release tests、fresh/upgrade/clear、验收矩阵、人工试用 | 发布前终审；GO 只授权本地安装 |

每个 Goal 必须写明 `authorized_through: R<n>`。未明确授权 R5 时，CLI adapter 只能保留 fake/fixture 实现；未明确授权外部 AI 时，R2–R4 只用 mock transport。

## 10. 验收矩阵

- [ ] 选定项目的数据不会混入同名项目、另一个 provider、另一个 profile 或另一个日期范围。
- [ ] 本地模式零网络、零正文读取；页面关闭后零新增 timer/watcher/worker。
- [ ] warm unchanged 复用现有快照，不重新扫描 JSONL。
- [ ] aggregate-only payload 不含项目名、路径、账号、thread/session ID、prompt/response 或未知字段。
- [ ] 内容模式逐次同意，精确预览与实际 body 字节一致，取消后不发送。
- [ ] secret/path/project/privacy canary 在 API、CLI、结果保存和导出四条路径都不能泄漏。
- [ ] malicious prompt/output 不能获得工具、改变 system contract、执行 HTML 或伪造 evidence。
- [ ] AI 结果引用不存在 evidence 时被拒绝；不足样本返回“证据不足”，不生成泛化建议。
- [ ] Token、成本、额度、预测和质量 proxy 在报告中分栏并带 coverage/置信度。
- [ ] timeout、取消、CLI 登录失效、额度不足、非零退出、超长输出和 malformed JSON fail closed。
- [ ] 原始内容、完整请求和原始 CLI 输出不持久化；结构化报告遵守有界保留和精确清除。
- [ ] 旧缓存迁移、窗口 reload、重复点击和 stale ACK 不重复调用或复活已清数据。
- [ ] 所有用户文案覆盖 8 locale，键盘/焦点/ARIA、深浅主题和约 360 px 通过。
- [ ] 文档准确说明：本机 CLI 不等于离线、AI 建议不是生产率/质量结论、插件不会自动执行建议。
- [ ] 真实发布前由 Codex 运行完整门禁，并让 Claude 对 spec、payload/security diff、建议语义和最终候选各做一次有界只读审阅。

## 11. 明确不做

- 不做项目/人员生产力评分、排行榜、跨用户 benchmark 或“哪个模型更强”结论。
- 不自动修改模型、effort、prompt、代码、CLAUDE.md、设置、issue 或 PR。
- 不后台调用 AI，不根据额度充足自动发送，不把一次同意扩展为永久授权。
- 不保存完整项目对话语料，不把 raw prompt/response 变成第二套索引。
- 不把 GitHub 连接、同步、公开分享或社区数据作为本功能前置。

## 12. 下一次启动条件

只有以下前置全部满足时才建议创建实现 Goal：

1. v2.3.1 已完成用户安装验证并确定发布/修订结论；
2. X-06 项目用量矩阵已接入稳定线或其 snapshot contract 已冻结；
3. v2.4.x comparison envelope 和本地反馈/清除语义可复用；
4. 用户明确本轮只做到 `R0–R4`，还是同时授权 `R5` 的本机 Claude CLI 安全门；
5. 数据契约、README/LOCAL-DATA 和清除清单计划与代码同版更新。

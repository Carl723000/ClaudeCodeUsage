# v2.3.0 Codex Dashboard Parity Design

**Date:** 2026-07-20  
**Chinese review copy:** [简体中文](2026-07-20-v2.3.0-codex-dashboard-parity-design.zh-CN.md)

## Goal

Make Codex Beta feel like part of the existing extension rather than a separate dashboard. Reuse the Claude dashboard's navigation, cards, charts, composition bars, tables, settings panel, localization, and number formatting wherever the underlying Codex data supports the same interaction.

Parity is semantic, not cosmetic at the expense of accuracy. Codex continues to show no invented dollar cost, does not inspect conversation or command bodies, and does not create empty Branches or Workflows surfaces when local logs cannot support them reliably.

## Approaches considered

1. **Exact Claude clone.** Copy Today, This Month, All Time, Content, Branches, and Workflows one-for-one. Rejected because several values would be missing, timezone-imprecise, or fabricated.
2. **Semantic parity (selected).** Reuse the established UI system and settings, but use truthful Codex-native ranges, metrics, and behavior diagnostics.
3. **Independent Codex analytics lab.** Keep the current standalone visual language and add more cards. Rejected because it preserves the inconsistency reported in local testing.

## Navigation and modules

Codex uses the same horizontal tab behavior and visual states as Claude:

1. **Recent** — latest root-task lineage, including child and approval-reviewer threads.
2. **7 Days** — rolling seven-day usage with daily chart and table.
3. **30 Days** — rolling 30-day usage with daily chart and table.
4. **All Time** — all indexed usage with a monthly chart and table.
5. **Threads** — recent indexed threads, sortable by time, role, project, model, effort, processed/fresh/output/reasoning tokens, cache share, and duration.
6. **Projects** — pseudonymous project aggregation using the same table language as Claude Projects.
7. **Behavior** — Codex-specific composition and local optimization signals.
8. **Settings** — the existing dashboard Settings panel, rendered directly in Codex mode. The toolbar gear opens this tab without switching to Claude.

The design intentionally uses rolling 7/30-day scopes rather than claiming calendar-accurate Today/This Month bucketing from the current UTC day aggregates. This avoids expanding v2.3.0 into a new timestamp-index migration. Content, Branches, and Workflows remain Claude-only.

## Visualizations

All visualizations reuse existing Claude CSS components and interaction patterns.

- The 7-day and 30-day tabs show a bar chart and table by active day.
- All Time shows a bar chart and table by month.
- Chart metric buttons switch among Processed, Fresh, Output, Reasoning, and Threads.
- Each time scope includes a **Token composition** bar analogous to Claude's cost composition: fresh input, cached input, and output are the three non-overlapping segments. Reasoning is displayed as a labelled subset of output and is never added again to the total.
- Behavior includes a **Thread-role composition** for root, subagent, and approval-reviewer fresh usage, plus effort and model breakdowns.
- Existing VS Code theme variables, spacing, summary cards, table hover states, and responsive overflow behavior remain authoritative.

Charts do not introduce a new visual design system and do not imply monetary cost.

## Codex behavior diagnostics

Behavior remains local and deterministic. It may show:

- subagent fresh-token share and child threads per root task;
- approval-reviewer fresh-token share;
- high/max/ultra effort share;
- processed-to-fresh amplification and input cache share;
- reasoning share within output;
- post-change command density and patch rounds;
- compaction count as a long-context signal;
- recent-task recommendations already supported by the approved Codex insight rules.

Recommendations describe correlations and structural proxies, not causation. No prompt, response, command, tool argument, raw path, session ID, credential, or private database content is read or rendered.

## Settings alignment

- Codex mode embeds the existing Settings panel rather than redirecting to Claude.
- Existing shared settings apply to Codex where meaningful: language, compact token counts, token decimal places, release announcements, dashboard auto-refresh, provider selection, Codex status metric, Codex home, and Codex watcher delay.
- Add `codex.optimization.enabled`, default on, to hide or show the Behavior/optimization surface without disabling Codex collection.
- Claude-only settings remain available in the shared panel but are not silently reinterpreted for Codex.
- No credential, subscription-cost, automatic config-editing, or conversation-content setting is added for Codex.

## Data and rendering boundaries

- Add an All Time scope and monthly rows derived from the existing numeric per-day aggregates.
- Keep the current bounded recent-thread list and expose its shown/total count.
- Pass the established `I18n.formatNumber` formatter into Codex rendering so compact-number preferences match Claude.
- Pass the already-rendered internal Settings HTML into the Codex renderer; it is trusted extension output, not log content.
- Preserve pseudonymous project labels and HTML escaping at every dynamic boundary.
- Do not change the Codex index schema or trigger a full-history migration for this dashboard increment.

## Stale-view handling and test package

The previous package was installed correctly, but an already-open Webview retained old HTML until the VS Code window reloaded. The handoff must therefore:

- use a distinct `codex-beta-r2` VSIX filename;
- verify the installed bundle contains the new tab marker;
- instruct testers to run `Developer: Reload Window` after a same-version local install;
- keep the internal release version at `2.3.0` so local testing does not distort release-announcement behavior.

## Testing and acceptance

- Scope aggregation tests cover all-time/month rows without double counting token subsets.
- Composition tests prove fresh input + cached input + output equals processed tokens and reasoning is not added twice.
- Behavior tests cover zero denominators, role shares, effort shares, and incomplete timestamps.
- Renderer tests require eight Codex tabs, Claude visual classes, charts, Settings content, localized copy, compact formatting, and no raw identifiers or dollar cost.
- Webview tests require the Codex gear to open Codex Settings and require independent Codex tab state restoration.
- Full TypeScript and repository tests remain green.
- The final VSIX is inspected for version, new bundle markers, forbidden files, and matching SHA-256 after copying to the project root.

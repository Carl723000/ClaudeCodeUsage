## User benefit

v2.3.1 converges existing advice into one verifiable loop. A user first sees the local aggregate evidence and success measure behind a recommendation, then chooses whether to use optional AI personalization. Afterwards they can record helpful, not helpful, and applied feedback, and compare tasks only when provider, task kind, complexity, measurement semantics, and quality guardrails match. When reliable pairs do not exist, the product says that evidence is insufficient instead of turning a fluctuation into a causal claim.

The same release adds Codex hour detail for the last 30 days. Every populated date reads the sparse hourly aggregate already maintained by the provider index, with zero raw JSONL reads on click. Claude and Codex share the configured timezone and `HH:00` label format.

## Furthest boundary for this candidate

- AI sending reuses only the existing legal BYOK or user-configured endpoint and occurs only after an explicit click. Refreshes, background work, and hidden pages never generate AI requests.
- The host prepares one `PreparedAdvicePayload`. Preview, byte count, SHA-256, retries, and the actual request body consume the same canonical UTF-8 bytes from that object. Reconstruction or disagreement fails closed.
- The default payload contains allow-listed aggregates only. Prompt personalization is a separate, default-off, revocable consent; only text supplied or explicitly selected by the user can appear verbatim in preview and send.
- Feedback, comparable pairs, and the versioned comparison-result envelope remain in bounded local state. They never store prompts, responses, sessions, paths, project names, raw records, or free-text feedback.
- Legacy Get AI Advice and Prompt Optimizer share the preparation, preview, send, parse, and feedback boundary. Optimizer still processes only the user's pasted draft and never treats a permissive text fallback as structured advice.
- Account center, authentication, multi-account switching, achievements, GitHub, default/background AI, version changes, default-setting changes, release-workflow changes, and publishing remain out of scope.

## Single data producer

- `ClaudeUsageIndex` remains the sole reader of Claude logs. The existing persistent provider index and its worker remain the sole readers of Codex logs.
- Advice, feedback comparison, hourly expansion, and the Webview consume only main-index aggregates or bounded projections carrying `provider + measurementProfileVersion + revision + coverage`. They do not create a second scanner, scheduler, or competing cache of truth.
- The Codex index maintains the sparse last-30-day `date -> hour` buckets during its normal incremental pass and evicts day 31 in the configured timezone. Its one-time fill migration runs in the existing Codex worker and shares the same durable progress state.

## Resource ownership and stop conditions

| Resource | Creator | Creation condition | Stop condition and disposer |
| --- | --- | --- | --- |
| Claude / Codex recurring timers and watchers | Existing window lifecycle coordinator in `extension.ts` | Provider enabled and window lifecycle permits work | Window loses focus, provider is disabled, or extension disposes; lifecycle coordinator disposes them |
| Codex index / backfill worker | Existing `CodexIndexClient` | Main index needs a cold build, compatible migration, or incremental work and E-03 allows execution | Completion, checkpoint at budget exhaustion, user pause, provider disable, or extension dispose; client terminates the worker. A bounded first-availability backfill may continue after focus loss but never after explicit pause, disable, or dispose |
| AI network request | Single host sender | User clicks Send after preview, the Prepared object is valid, and BYOK configuration is legal | Response, error, user cancellation, consent withdrawal, feature disable, or extension dispose; the sender cancellation owner aborts it. No retry timer or background poll exists |
| Advice projections and comparison | No long-lived resource | Pure projection on a changed main-index revision, local feedback, or on-demand visible render | Released synchronously; no recomputation or render while hidden or disabled |
| E-03 progress record | Main-index durable state | First migration or backfill need | Not a runtime resource; completion retains only version, verified position, `failStreak`, `nextEligibleAt`, `pausedReason`, and required counters |

The E-03 success path continues immediately without an artificial delay. Only failure, lack of progress, or explicit pause creates a durable cooldown. Ordinary refresh, watch, focus, reset, menu open, or extension upgrade cannot bypass `nextEligibleAt`. Restart resumes from the verified checkpoint.

## Zero additional long-lived resources when off

Relative to v2.3.0, a disabled, unconsented, unsent, or hidden advice loop owns zero new timers, watchers, workers, network requests, log enumeration/body reads, and hidden Webview renders. After the Codex base-index migration finishes or stops, the resource inventory returns to baseline; no empty loop remains for hypothetical future work.
